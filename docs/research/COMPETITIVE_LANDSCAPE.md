# Competitive research — product positioning

Competition already solves parts of contribution discovery. Distinguish Contributor on the complete workflow, not a claim that no issue finder exists.

| Product/source | Existing value | Contributor differentiation target |
|:--|:--|:--|
| GitHub Search | Powerful repo, issue and PR search syntax | A human-centered guided discovery flow and relevance explanations |
| goodfirstissue.org | Curated entry-level issues | Support more skill levels, review opportunities and assistant handoff |
| up-for-grabs.net | Maintainer-curated beginner opportunities | Personalized fit and repository readiness context |
| CodeTriage | Issues from selected repositories | Discover repos *before* the user knows what to follow |
| CodeRabbit | AI code review for installed repos and CLI users | Optional evidence, not a required platform subscription |
| OpenCollab MCP / GitSense | Personalized open-source discovery tools | Memory-aware client interoperability + review-first journey + free web baseline |

## Critical hypotheses to test

- Users struggle more with picking a healthy, welcoming repository than with Git syntax.
- A deterministic match with evidence is trusted more than an opaque AI difficulty label.
- Review-first contributors need a different onboarding journey than feature implementers.
- Hermes users value scoped use of memory rather than copying their stored memory into a new app.
- Users prefer BYOK over paying multiple platforms for the same LLM access.

All of these are **hypotheses** until tested. See [research sources](SOURCES.md).
